# 変更履歴

このプロジェクトのすべての重要な変更は、このファイルに記録されます。

フォーマットは [Keep a Changelog](https://keepachangelog.com/ja/1.1.0/) に基づいており、
バージョン番号は [Semantic Versioning](https://semver.org/lang/ja/) に従っています。

## [Unreleased]

## [1.5.8] - 2026-10-05

### 追加
- 患者台帳の画面上部（禁忌ボタンと手術予約ボタンの間）に、紹介状の宛先を表示する欄を復活させた（2026-07-02 のリファクタリングで削除していたが、再び必要になったため）
  - 眼科（診療科コード 7）が差し出した返事（眼科・途中・最終）のうち最新の 1 件を「病院名 宛先科 宛先医師 先生」と表示する
  - 欄をダブルクリックすると、その患者の過去の紹介状を一覧で表示する
  - 欄を戻した分、Inno・Grapa・PDF ボタンを右へ 350px ずらした
  - MedicalLibrary に `Intro`（紹介状の取得）を戻したため、`EyeData.exe` と `MedicalLibrary.dll` をセットで配置すること

## [1.5.7] - 2026-10-02

### 削除
- 患者IDのみ（1～9 桁）のバーコードを読み取って患者台帳を開く機能（1.5.4・1.5.5 で追加）を削除した
  - 数字 2～3 桁＋Enter を素早く手入力したときにバーコードと誤認され、入力が取り消されて患者台帳が開くおそれがあったため
  - バーコードとみなすのは数字 36 桁＋Enter（オペ録・申し送り書）のみ。1～9 桁の数字と Enter は入力の速さに関係なくそのまま画面に渡る
  - 患者IDのみのバーコードをメイン画面で読み取ると、1.5.3 以前と同じく Enter で「患者台帳」ボタンが押され、ID の入っていない患者台帳が開く（患者台帳の患者ID欄で読み取れば、その患者が読み込まれる）

## [1.5.6] - 2026-10-02

### 追加
- 患者台帳の手術基本情報に「短期滞在手術等基本料3」のチェックを復活させた（禁忌確認と締切後手術の間。2026-07-02 のリファクタリングで削除していたが、再び必要になったため）
  - 手術一覧画面に「短3」列を戻し、チェックした手術は手術一覧の印刷にも「短3」と出る
  - DB の `EYE_OPE.SHORT_OPE3` 列と MedicalLibrary の `EyeOpe.ShortOpe3` は残っていたため変更なし
  - 削除していた間（2026-07-02 以降）に保存した手術情報は 0（チェックなし）で保存されている

### 修正
- `EyeData.xml` の申し送り項目（`OpePassItem`）で、「Realavg」の閉じタグが抜けて「avgK」が入れ子になっていたのを直した
  - 閉じタグが「avgK」の後ろに余っていたため、正しい位置に移した（`EyeDataXmlTests` の失敗も解消）

## [1.5.5] - 2026-09-29

### 修正
- 患者IDのみのバーコードを 1 回で患者台帳に開ける桁数を 1～6 桁から 1～9 桁に広げた（7～9 桁の患者IDでも ID の入っていない患者台帳が開いていたため）
  - 所要時間の上限（100 ミリ秒）は変えていない

### 変更
- 手術記録検索画面の Excel 出力・CSV 出力で、サマリー列を追加する処理を共通メソッド（`AppendSummaryIfChecked`）にまとめた

## [1.5.4] - 2026-09-28

### 修正
- 患者IDのみ（1～6 桁）のバーコードを読み取っても 1 回目は ID の入っていない患者台帳が開き、2 回目でようやく ID が入っていたのを、1 回で読み取った患者の患者台帳が開くようにした
  - 数字 36 桁のバーコードしか判定していなかったため、Enter でメイン画面の「患者台帳」ボタンが押されていた（2 回目は患者台帳の患者ID欄の Enter で読み込まれていた）
  - 数字 1～6 桁＋Enter が 100 ミリ秒以内に入力されたものを患者IDのバーコードとみなすようにした（手入力と区別するため、36 桁の判定より短くしている）

## [1.5.3] - 2026-09-28

### 修正
- バーコードを読み取っても 1 回目は ID の入っていない患者台帳が開き、2 回目でようやく ID が入っていたのを、1 回で読み取った患者の患者台帳が開くようにした
  - 1 文字ごとの打鍵間隔（50 ミリ秒以内）で判定していたため、リーダーの送信間隔のばらつきでバーコードと認識されず、Enter でメイン画面の「患者台帳」ボタンが押されていた
  - 数字 36 桁＋Enter の所要時間で判定するようにした。上限は設定ファイルの `BarcodeKeyInterval` で変更できる（既定値 1000 ミリ秒）

## [1.5.0] - 2026-09-26

### 追加
- バーコードリーダー（キーボード入力方式）で 36 桁バーコード（オペ録・申し送り書）を読み取ると、先頭 9 桁の患者 ID の患者台帳を開くようにした
  - EyeData のいずれかの画面がアクティブなときに有効（背面にあるときは反応しない）。文書コードに関係なく常に患者台帳を開く
  - 打鍵間隔が短い数字 36 桁＋Enter をバーコードとみなし、手入力とは区別する。間隔の上限は設定ファイルの `BarcodeKeyInterval` で変更できる（既定値 50 ミリ秒）
  - 読み取りで入力欄に入った数字は元に戻し、Enter は画面に渡さない（既定ボタンなどが押されない）
  - 別の患者を表示中の場合は、登録していない入力内容が破棄されるため、切り替えてよいか確認する（既定は「いいえ」）
  - 患者が見つからない場合はその旨を表示する。検索画面などのダイアログ表示中は開かずにビープ音を鳴らす

### 変更
- 患者台帳のタイトルバーの表記を「EyeData (〇〇 ログイン中)」に調整した

## [1.4.0] - 2026-09-25

### 追加
- メイン画面に「ユーザー変更」ボタンを追加し、アプリを終了せずに ID・パスワードで別のユーザーに切り替えられるようにした
  - ユーザーが変わった場合は、前のユーザーの画面を残さないよう、メイン画面以外の画面をすべて閉じる（保存していない入力は破棄される）
  - キャンセルした場合や同じユーザーでログインした場合は何もしない
  - 切り替えたユーザーは、アプリを終了するまで電子カルテ（Pat.csv）のユーザーより優先する（電子カルテから再度呼び出されても戻らない）
- メイン画面の下部にログイン中のユーザー名を表示するようにした
